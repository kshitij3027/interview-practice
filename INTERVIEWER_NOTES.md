# POST-PRACTICE ONLY — RackFit interviewer notes

Do not open during the candidate exercise.

## Intended structure and strong solution

This is an online sparse extent allocator with first-fit selection in a two-level ordering, five alignment classes, mutable reservations and exactly-once logical operations. It is not a scheduling or offline optimization problem. Preprocess each volume's permanent intervals by sorting/merging overlapping or touching spans and take their complement. Maintain maximal disjoint free intervals [l,r). For alignment a, capacity of a free interval is max(0,r-ceil(l/a)*a). Store its value for each of the five classes, and subtree maxima for each class in an augmented balanced search tree keyed by (volume order,l), separately per pool. Descend left first whenever the left subtree's maximum for the requested class is >= blocks, otherwise test current interval then right. This yields exactly the earliest feasible volume and address. A randomized treap is a practical implementation; deterministic AVL or another balanced ordered structure also works. An allocation deletes the chosen free interval and inserts the nonempty prefix and suffix. Release finds neighboring intervals in the same volume, merges only exact adjacency with them, and reinserts. Never merge across volumes. A dictionary maps reservation ID to location; another maps event ID to normalized input and immutable result. Check replay before consulting active state. A failed allocation or missing release is still a replayable result. Use integer arithmetic.

Let P be permanent rows, V volumes, F current free intervals across a pool, A=5 alignment classes, E distinct valid operations. Preprocessing O(P log P + V + A F log F) with ordinary insertion (or linear construction from sorted intervals after sorting); allocation/release expected O(A log(F+1)) with a treap, worst case O(A F) for adversarial priorities/unlucky shape, or worst-case logarithmic using balanced deterministic trees. Space O(P+V+A F+R+E) including raw catalog, active reservations R and replay. F is bounded by V + P + R. A per-volume tree plus an outer ordered volume index with class maxima is also strong; O(A(log F_v + log V_pool)). Scanning at most 256 volume summaries per request may be defensible with measured evidence, as long as it never scans the hot volume's intervals. Consider Python object overhead of five maxima, replay payloads and tree nodes; use slots, compact tuples and reference reuse where appropriate. Benchmark the actual environment; no promise that any specific implementation meets 45 seconds.

## Naive failures and alternatives

Bitmap or address enumeration fails at 10^12 blocks. Scanning every occupied/free span per allocation degrades quadratically under repeated misses. A heap ordered by length alone cannot guarantee earliest address or volume; raw length ignores alignment. A sorted Python list has O(F) insertion/deletion even with binary search. A sparse implicit segment structure may work with careful summaries for alignment and cross-boundary free runs but needs memory analysis (log capacity per change). A block-decomposed ordered structure with per-block aligned maxima is an acceptable engineering compromise if quantified under churn. A database range index alone does not prove first-fit performance. LLMs can assist design or explain results, but exact state transitions should be mechanically verified; heuristic search may be used if it never sacrifices exact choice or falsely reports no space.
